# Recommendations implementation

The remaining five implementation workstreams are implemented in the existing runner, scheduler, router and state store. New CLI runs use the [checked-publication policy](lean-execution-profile.md); historical runs require explicit stopped-run upgrade before CLI execution. The legacy preset and broad upstream repair have been retired. Compatibility code for historical records and external controller authority remains and is not a second advertised user workflow.

- Structured reviewer bodies contain verdict plus grounded findings. The caller owns identity, source/context fingerprints, policy and timestamps. Supported Codex and configured generic adapters use designated final artifacts. Task, planning and final reviews have review-only protocol recovery and durable adapter circuits. A late valid response cannot reopen an already opened circuit.
- Shared implementation/repair counters and total task deadlines persist before dispatch. Resume, retry, fallback and amendments cannot reset them. Conflict and substantive repairs share that allowance; infrastructure and protocol recovery remain separate bounded phase routes. Repeated unchanged failures stop early.
- Detached merge candidates run executable acceptance before conditional Git ref publication. Durable intents and source-bound receipts distinguish unpublished candidates from published work with unfinished task state. Failed candidates retain pinned revisions and diagnostics. State failure after publication stops dispatch; restart finishes acceptance without another worker invocation.
- Deterministic fragment import pins a shared Git baseline, namespaces requirement provenance, merges explicitly shared producers and rejects source, identity, interface and coverage conflicts before compilation. Host-aware ownership admission handles Windows case, directory overlap and filesystem aliases.
- Artifact-based risk routing, required selected-test counts, phase and integration queue timings, wait reasons, ready widths and integrated requirement throughput are available through the existing router and status reporting.

Implementation and review evidence remain separate milestones. A selected reviewer cannot edit source or disappear behind an inapplicable condition. The original worker checkpoint stays pinned, and publication rejects a landing tree changed after local acceptance. Actual combined candidate checks certify publication; task-local checks do not certify a different merge. Already accepted boundaries are conservatively rechecked rather than relying on an unproven impact classifier. Main promotion remains a deliberate user action; the runner never advances the user's checked-out main branch behind its index.

Validation includes real Git parallel producer/consumer visibility, a clean textual merge that fails behavioral checks, resource/write contention, invalid reviewer reports, provider circuits, zero selected tests, bounded attempts/deadlines, and process/state interruption around publication. A fixed 24-task, eight-component batch with concurrency three accepted all 24 requirements and produced 24 verified publication receipts. The [batch record](build/recommendations-lean-batch.json) includes exact baseline, manifest, settings and executing-build fingerprints. It uses deterministic workers, so its throughput is an execution-policy regression measurement, not a prediction of coding-model throughput. Real model runs using the original workload are still needed to compare model quality and production throughput. Failed test-run logs remain in the orchestration workspace.

The full repository suite passed 448 tests. Subsequent hardening passed 75 targeted tests across review, integration, execution budgets, fragment import, admission, test counts and transport. All four final integration tests passed, including a source edit injected after local acceptance. The TypeScript build and Git whitespace checks also passed. Bulk prompts for supported non-Codex adapters use file-backed payloads; Codex uses stdin and the installed 0.149.0 CLI supports the required final-output, schema and sandbox options. Lean Codex workers use workspace-write and reviewers use read-only sandbox flags. Worktrees themselves remain source isolation rather than a general security boundary.
