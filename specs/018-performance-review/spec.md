# Performance review

Exercise the important user journeys in the integrated product under repeatable conditions. Record the commands, environment, workload and baseline used. Measure relevant startup, navigation, build or test times, memory use, and responsiveness where the application makes those meaningful. Repeat noisy measurements and report their spread. Compare against explicit product requirements or a comparable existing version. Avoid inventing a pass threshold where none exists.

Write a concise report with raw measurements or their saved location, the observed bottleneck, reproduction steps and any regression supported by the evidence. Identify slow operations the QA worker can address within its scope. Mark measurements that the available environment cannot support. After repairs, repeat the same measurement and record the result.
